# 매물 문서 첨부 — 비공개 원본 보관

## 브라우저 XLSX 셀 편집

문서 목록의 `엑셀 열기·수정`에서 셀의 글자와 숫자를 편집합니다. 수정본은
`원본명_수정_한국시간_구분값.xlsx`라는 별도 첨부로 같은 매물에 업로드하며 원본을
덮어쓰거나 삭제하지 않습니다. 기존 다운로드·업로드 API와 직원 권한을 재사용합니다.
새 DB 테이블·공개 URL·서버 디스크 저장·외부 편집 서비스는 추가하지 않습니다.
원본과 수정본은 각각 저장 용량 및 전송 사용량에 포함됩니다.

사진·도형·차트·스타일·병합·열 너비의 원본 ZIP 구성은 보존합니다. 일부 개체와
표시 형식은 브라우저 미리보기에서 생략될 수 있습니다. 수식 셀, 배열 수식 영역,
보호 시트는 편집하지 않습니다. 셀 수정 후 수식 캐시는 제거하고 Excel에서 전체
재계산하도록 표시하므로 브라우저는 계산 결과를 확정하지 않습니다. XLS 파일,
암호화 파일, 매크로·전자서명 문서는 다운로드 후 별도 프로그램에서 수정합니다.
XLSX 파일 30MiB, 압축 해제 96MiB, ZIP 구성 10,000개, 시트 150,000셀 제한이
있으며 화면은 100행·26열씩 이동합니다. 편집 중 자료는 브라우저 메모리에만 두고
닫기 확인·미저장 이탈 경고를 제공합니다. 기존 문서 목록은 원본을 자동 다운로드하지 않습니다.

회귀검증: 실제 사용자 제공 6시트 양식에서 숫자·글자 수정 후 재개방, 사진 파일과
스타일의 바이트 일치, 두 시트의 사진 배치, 병합·글꼴·너비·수식 유지 확인.
모의 서버로 저장 실패 후 재시도·매물 ID·별도 수정본 업로드를 검증했습니다.
운영 직원 세션을 통한 실제 수정본 업로드는 아직 직접 확인하지 않았습니다.

문서 원본은 기존 NAVER Cloud 비공개 버킷의 documents/{UUID}/original.{확장자}에 저장합니다. 서버 디스크·GitHub에 파일 원본을 넣지 않습니다. Supabase에는 파일명·해시·크기·매물 ID·소프트 삭제·업로드 임대 정보만 저장합니다.

지원: xlsx, xls, pdf, docx, doc, pptx, ppt, hwp, hwpx. 파일당 30MiB, 문서 전체 1,000,000,000바이트(삭제·예약 포함). 이 제한은 무료 제공량이나 금액 상한이 아닙니다. 원본을 변환하지 않습니다. 일부 암호화 Office 문서는 파일 헤더 검사에서 거부됩니다. 매크로 확장자(xlsm 등)는 받지 않습니다. 서버에서 문서 실행이나 내용 미리보기를 하지 않으며 다운로드는 attachment/octet-stream으로만 제공합니다. 파일 헤더 검사는 바이러스 검사나 문서 내부 형식 전체 검사를 의미하지 않습니다.

사진 직원 권한(can_read/can_edit)을 재사용하고 모든 API에서 인증·직원권한·매물 존재·문서 연결을 검사합니다. 다운로드 티켓은 60초, 사용자·매물·파일에 묶이고 실제 요청에도 Bearer 인증이 필요합니다. 비공개 객체 URL이나 키는 브라우저에 전달하지 않습니다.

계정 설정과 비용: 같은 NAVER 버킷/키 및 기존 LM_PHOTO_* 비밀값을 새 landmaker-documents 함수에서 사용합니다. 새로운 유료 플랜은 필요하지 않으며, 저장·요청·인터넷 전송료는 사용량만큼 발생합니다. 사진/문서 요청 횟수는 기존 사진 meter를 공동 사용합니다. 사진 저장 앱 제한(8GB)과 문서 저장 앱 제한(1GB)은 별개입니다. 사진 비용 화면은 문서 보관료를 제외한다고 표시합니다. 목록 조회는 파일 원본을 내려받지 않습니다.

운영 적용 순서:
1. 운영 DB 추가 변경 승인 후 schema-proposal.sql을 적용합니다. 추가 테이블 lm_document_files 1개와 RPC lm_document_dispatch만 만들며 기존 데이터는 수정/삭제하지 않습니다. 기존 photo_audit와 photo_meter에는 문서 사용 시부터 기록됩니다. anon/authenticated 직접 접근은 금지합니다.
2. supabase/functions/landmaker-documents/index.ts와 상대 의존성을 배포합니다. 새 함수는 직접 Supabase Auth로 토큰을 검증하므로 verify_jwt=false를 사용합니다.
3. 실제 테스트 문서 1개로 업로드·다운로드 원본 일치·삭제·복원·권한 차단을 확인합니다. 테스트 파일은 삭제 연결 상태로 보관하며 물리적 삭제하지 않습니다.
4. 승인받은 기능 브랜치의 프론트엔드를 main에 반영합니다. 사진 함수는 재배포할 필요 없습니다.

검증: 로컬 PGlite 실제 SQL과 메모리 객체 저장소로 업로드/중복/매물 격리/다운로드 바이트 일치/소프트 삭제/복원/감사 기록, RLS/RPC 직접 접근 차단/직원 권한/요청 한도/Origin 차단/파일 형식·크기 검사를 실행합니다. 실제 NAVER 문서 업로드와 모바일 파일 선택은 운영 승인 이후 확인해야 합니다.

2026-11-19 사용자 승인 후 운영 테이블·RPC를 추가했고 landmaker-documents 함수 v1을 배포했습니다. 운영 RLS/직접 접근 차단과 usage RPC를 확인했습니다. 문서·사진 테스트 25개 및 목록 이동·로그인 테스트를 통과했습니다. 실제 직원 로그인으로 NAVER 원본 업로드·다운로드는 테스트 브라우저에 로그인된 탭이 없어 아직 확인하지 못했습니다.
보안 점검: lm_document_files의 RLS 무정책 INFO는 모든 클라이언트 직접 접근을 차단하고 service_role 서버만 허용하는 의도된 설정입니다. 기존 함수/인증 설정 경고는 이 변경 범위에서 수정하지 않았습니다.
